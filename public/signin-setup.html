One-time setup for the site owner

Connect email sign-in.

The app’s email-code flow is implemented. A real authentication service and sender must be configured before public visitors can sign in. Guest activities remain available.

1. Create a Supabase project

Use your own Supabase account. No application database tables are needed for this release. Keep the database password private.

2. Enable email and a sender

In Authentication, enable the Email provider and new signups. Configure custom SMTP with a verified sender. Supabase’s default sender is restricted and cannot support general public sign-in. Choose a provider and plan appropriate to your usage.

3. Send a code

In Email Templates → Magic Link, include {{ .Token }} in the message so the user receives a one-time code. Set the code expiry and provider rate limits. The app asks for the code in the same browser tab.

4. Configure the site

Set Site URL to https://reasonlab.simstart.workers.dev. Add https://reasonlab.simstart.workers.dev/account.html to allowed redirect URLs. Get the project URL and publishable key from the project API settings.

Share only those public configuration values with the developer. Never share a secret key, service-role key, SMTP password or Google client secret in chat, GitHub or browser code.

5. Enable and deploy

The repository contains scripts/configure-auth.mjs. The developer runs it with the project URL, publishable key and --email, then tests and deploys. Google sign-in is separate and can be enabled later.

6. Verify a real sign-in

Test email delivery, a correct code, an incorrect/expired code, sign-out and local history separation. Test one Gmail address and one other email provider using authorised adult accounts.
